## 一、接入场景简介

### 场景一：网约车出行服务

用户在打车 App 内下单后，从等待接单到行程结束的全流程信息展示。用户可在桌面岛区域实时查看司机位置、预计到达时间、车辆信息等关键状态，无需反复打开 App。

### 场景二：外卖配送服务

用户在外卖平台点餐后，从商家接单到骑手送达的全流程跟踪。关键节点包括商家接单、骑手取餐、配送中、已送达，每个节点自动更新岛内容。

### 场景三：倒计时提醒

用户设置倒计时/正计时后，在桌面区域持续显示剩余时间。适用于番茄钟、休息提醒、烹饪计时等场景。

## 二、场景节点全集

### 场景一：网约车出行

| 节点 | 说明 | 出现时机 | 自动展开 | 展示时长 |
|------|------|---------|---------|---------|
| 等待接单 | 用户下单成功，平台匹配司机中 | 用户下单后立即 | ✅ 是 | 持续至下一节点 |
| 司机已接单 | 司机接单，展示司机名、车牌、车型、预计到达时间 | 司机接单后 | ✅ 是 | 持续至下一节点 |
| 司机到达 | 司机已到达上车点 | 司机点击「已到达」后 | 否 | 5分钟 |
| 行程中 | 已出发，展示预估到达时间、路线信息 | 司机出发后 | 否 | 持续至下一节点 |
| 行程结束 | 到达目的地，展示费用信息 | 司机点击「结束行程」后 | 否 | 30分钟后退化为普通通知 |

### 场景二：外卖配送

| 节点 | 说明 | 出现时机 | 自动展开 |
|------|------|---------|---------|
| 已接单 | 商家已接单，展示预计送达时间 | 下单成功后 | ✅ |
| 骑手取餐 | 骑手已到店取餐，展示骑手名 | 骑手点击「取餐」后 | ✅ |
| 配送中 | 骑手出发配送，展示距离 | 骑手出发后 | 否 |
| 已送达 | 外卖已送达 | 骑手点击「送达」后 | 否 |

### 场景三：倒计时提醒

| 节点 | 说明 | 出现时机 | 自动展开 |
|------|------|---------|---------|
| 计时开始 | 用户设置并启动计时 | 用户操作后 | ✅ |
| 计时更新 | 剩余时间实时变化（调用 update 接口） | 每秒 | 否 |
| 计时结束 | 时间到，显示结束提示 | 计时归零 | 否 |

## 四、展示时长

### 通用参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `timeout` | 30~120 分钟 | 通知卡片自动消失时间 |
| `islandTimeout` | 300~3600 秒 | 岛形态自动消失时间 |
| `islandFirstFloat` | true | 首次出现时自动展开为展开态 |
| `enableFloat` | false | 更新时是否自动展开 |
| 展开态默认展示 | 5 秒 | 5 秒后自动收回摘要态 |

### 消失策略

- 每个场景结束时调用 `cancel=true` 主动清除岛通知
- 未主动清除时，岛 5 分钟后自动消失（`islandTimeout=300`）
- 通知卡片最长保留 60 分钟后自动消失（`timeout=60`）
- 用户可手动下拉或滑动清除

## 五、交互设计

| 交互 | 说明 |
|------|------|
| 展开/收起 | 点击岛区域展开详细信息，5 秒后自动收起 |
| 滑动切换 | 多服务时，左右滑动切换不同通知 |
| 下拉小窗 | 下拉岛区域转换为独立小窗进行应用内操作 |
| 拖拽分享 | 拖拽岛内容分享至微信/QQ/短信/浏览器 |
| 点击通知 | 点击通知卡片唤起对应 App 页面 |

## 七、SDK 和技术接入说明

接入方式：**客户端实现**

实现步骤：
1. 在 `AndroidManifest.xml` 中配置 `APP_ID` 和 `BUILD_TYPE_DEBUG`
2. 构建 `Notification.Builder` 创建通知
3. 在 `notification.extras` 中添加 `miui.focus.param` 键
4. 调用 `NotificationManager.notify()` 发送

不需要应用保活时，可使用 **MiPush 服务端推送** 方式：
1. 集成 MiPush SDK
2. 在 MiPush 消息的 `extra` 中添加 `miui.focus.param` 参数
3. 通过 MiPush API `vip.api.xmpush.xiaomi.com` 下发
